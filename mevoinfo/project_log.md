Channel map (all plaintext): UDP 1248 = XML discovery; TCP 5100 = binary `F0…F1`-framed control + 8-bit sample stream (subtypes `d3 cf`/`cd`); TCP 1258 = JSON Golf Video Processor (triggers/config/status/logs); HTTP 8080 = MJPEG camera (mjpg-streamer); UDP 123 = NTP time sync.

**BREAKTHROUGH (full-swing session, validated):** for FULL SWINGS the radar path DOES put metrics on the wire (TCP 5100), unlike putts (camera/GVP). The **github.com/divotmaker/ironsight** `docs/` (WIRE.md/SEQUENCE.md/CAMERA.md) decode the protocol and matched our capture exactly. Frame = `F0 DEST SRC TYPE payload CS_HI CS_LO F1`; addresses APP=0x10, PI=0x12, AVR=0x30, DSP=0x40; the ubiquitous `AA` = STATUS type. **Byte-stuffing** (FD escapes: F0→FD01, F1→FD02, FD→FD03, FA→FD04) and **frames span TCP segments → must reassemble**. Shot result types (AVR→APP): D4 FLIGHT_RESULT, E8, ED CLUB(×2/shot), EF SPIN, D9 SPEED_PROFILE, E5 text, EC PRC raw points. **D4 decoded = `[1 byte]+52×INT24-BE`; field f5 (payload offset 16) = BALL SPEED in mm/s — CONFIRMED** (matched device-reported Vb to 0.1 m/s, CoV 0.0005). f0=shot#. Candidates: f7=launch angle (mdeg), f8/f11=distance(mm), f9/f46=spin. **Displayed carry is app-computed (flight model), not a stored field.** Full writeup appended to `Documents\mevo_protocol.md` Section 6.

**PUTT path (still true):** metrics computed app-side from camera video (GVP, port 8080/1258), not on the captured wire; TCP 5100 `d3` stream there is compressed-camera-like, not radar ADC. The `mevo_iq_*.{bin,csv}` FFT extraction was the wrong tree for putts. Putt ground truth that confirmed this: 34'3" / 12.3 mph / 7.4°L → 0 float/ASCII hits in `mevo_putting.pcapng`.
